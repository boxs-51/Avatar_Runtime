# Optional dynamic Cubism adapter — implementation plan (2026-10-18)

**Status:** proposed design; `HOLD_DYNAMIC_LIVE2D`. **Stack parent:** draft PR #45 at `58425b2ff1684f2610fc7da146f2877760520cb7`, itself based on the open PR #37. This document authorizes no SDK download, public activation, binary redistribution, ABI change, or gate promotion. The v0.1 specification explicitly excludes proprietary Live2D integration; this is a candidate post-v0.1 optional adapter. Its eventual release needs a scope/ADR decision and applicable license review. Existing D06/D08 physical-loss and G00–G05 HOLD verdicts are independent.

## Objective and current evidence

`scripts/cubism_static_preview.py` packages a supplied portrait as one static ARS2D quad. The local `ulvm2_0002` portrait passed native ARSCHAR validation, private 2D scene preparation and three WARP pixel readbacks on PR #45. This proves only the portrait path. The model's actual drawable meshes and parameter deformation are inside `.moc3`; the [official Core reference](https://docs.live2d.com/en/cubism-sdk-manual/cubism-core-api-reference/) says Cubism Core computes the vertices and exposes rendering data. The [official Core distribution page](https://docs.live2d.com/en/cubism-sdk-manual/cubism-core/) says Core is supplied in SDK packages and is not published on GitHub.

The owner's local model has one 2,727,808-byte MOC3, five referenced PNG atlases, one referenced physics JSON and one referenced display-info JSON. Its `model3.json` declares no motions or expressions; 35 `.exp3.json` files exist only in the separate `animation/` folder. Do not infer that arbitrary sidecar files are active model resources. The owner allows free use but **forbids publishing this model in the public repository**. Source, converted output, pixels, screenshots, logs containing asset content, and the SDK's proprietary Core must remain out of public commits and CI artifacts unless their separate distribution terms are established. A report may contain counts, hashes, test verdicts and nonsensitive device metadata.

**L0 budget finding (2026-10-18):** the five 4096×4096 RGBA atlases imply 335,544,320 decoded bytes (320 MiB), versus the current ARS v0.1 private asset parser's 134,217,728-byte pixel limit (128 MiB). The separate L0 preflight can inventory the sample but does not make it admissible to the existing ARSCHAR parser. Before L1, choose and test a private Cubism texture budget and residency strategy with host accounting; do not quietly raise the v0.1 global limit. Until then the sample also has `HOLD_TEXTURE_BUDGET`.

The target is a **locally loaded, parameter-driven dynamic Cubism model** rendered into the existing host-owned D3D11 offscreen target. The first accepted scope is default pose, at least two distinct parameter-driven poses, ordered drawables, atlas sampling, opacity/blend and masks used by the sample, resize and lifecycle. Physics and expressions follow as explicit slices because a pixel-changing parameter test alone does not establish their behavior. Cubism motion clips are outside this sample's declared model3 resources. No silent fallback to the portrait can count as dynamic acceptance.

## Decision to freeze before implementation

| Approach | Goal / compatibility | Complexity and failure boundary | Rollback / evidence |
| --- | --- | --- | --- |
| **A. Optional native Cubism Core adapter plus D3D11 drawable renderer (proposed)** | Reads real MOC3 parameter values and drawable geometry; can render on the host device if every used mask, blend and offscreen feature is implemented. | Must bind versioned Core APIs, honor Core/Framework license, build a bounded projection, and reproduce Cubism draw order, masking and texture/color semantics. In-process parsing of a proprietary model requires an explicit trust/security decision before public use. | Private build flag defaults OFF; disconnect the adapter and retain ARS2D/GLB paths. Compare frames with an independently rendered official SDK reference. |
| B. Official Cubism renderer in an isolated helper, transferring completed frames | Better renderer fidelity and process isolation for MOC3 parsing; transfer to a host D3D11 target still needs an owned interop/copy protocol. | Extra process, IPC/shared texture or CPU readback, synchronization, frame latency and device-loss custody. Host-state and resource ownership are harder to prove. | Disable the helper without changing core ABI; compare transfer pixels and failure/restart traces. Use if A cannot safely support the sample's drawable features. |
| C. Convert sampled frames/meshes into ARS2D | Reuses native pipeline for a bounded pose subset. | Cannot preserve arbitrary continuous deformation, physics, masks and expressions without a new format and large bake. It does **not** satisfy the dynamic goal. | Keep only as an explicit offline fallback, never as proof that HOLD is closed. |

Choose A for the first private spike **only if** the licensed SDK and sample feature inventory make its renderer feasible. Reconsider B after one bounded spike if the sample requires Core features the current D3D11 pass cannot represent without major schema or device-ownership changes. Any public `.model3.json` source type, capability bit or ABI/schema change is a separate ADR and compatibility review, not an incidental consequence of this plan. The L0 probe must bind APIs by the pinned Core version; the [Core reference change log](https://docs.live2d.com/en/cubism-sdk-manual/cubism-core-api-reference/) records render-order and offscreen API changes, so names/semantics cannot be guessed from an older sample.

### Import and rendering boundaries

- The adapter treats model3 paths as untrusted. Resolve relative paths inside the local asset root, reject traversal/symlinks escaping it, duplicates, absent files, unsupported extensions and excess sizes before Core or D3D work. Core's version/validation functions must run before creating a model; a four-byte `MOC3` magic is insufficient.
- Core and Framework objects, texture storage, the immutable draw snapshot, host target and query have separately documented owners and teardown order. Parameter update and Core access stay on the designated thread; the renderer sees only the committed snapshot. Device loss quarantines that generation. Safe WARP injection does not lift D06/D08 physical HOLD.
- The D3D11 pass must match the sample's actual feature inventory. Core exposes drawable data, but the existing ARS2D quad renderer cannot be reused as a faithful Cubism renderer by simply swapping the texture. New clipping/blend/offscreen behavior needs pixel tests and a state-restore inventory.
- The official reference frame must be produced locally from the same model/parameters and SDK version. Store numeric comparisons and hashes in public CI reports, not the owner's proprietary images. Synthetic or separately licensed models can provide public CI coverage; the owner's model remains an opt-in local test that must be rerun at the pinned implementation SHA.

## Evidence and decision gates

| Requirement | Smallest convincing oracle | Public CI | Owner's local sample |
| --- | --- | --- | --- |
| Safe admission | path/version/size/duplicate/malformed negatives before Core/GPU | Synthetic model3 and adapter stubs | Official Core validation/version + local asset refs |
| Real deformation | default → two parameter poses → reset, distinct and repeatable vertex/pixel hashes | Test double or redistributable model if available | Required; image/geometry hashes only leave machine |
| Render fidelity | numeric RGBA pixel matrix for UV, order, blend, mask, resize; official reference | Redistributable fixture or shader unit targets | Required on WARP, then named GPU |
| Physics / expression | fixed-step trace, selected expression fade and precedence | Synthetic configuration where license permits | Required for a claim of full sample support |
| Lifetime | fault injection, exact query pins, 100 close/resize cycles, live-object identity | Platform-appropriate private tests | Required integrated Windows run |
| Public activation | linked C consumer, truthful capability and full gate reevaluation | After separate ADR/ABI approval | Cannot be inferred from private tests |

**Rework budget:** one SDK/API spike and one D3D11 drawable spike, each ending in a short evidence note with exact version/SHA and an explicit feasible/unsupported decision. If either cannot satisfy the sample's required features, stop that approach and review B or a narrower explicitly named scope; do not repeatedly patch render output to match one screenshot. No benchmark target is invented here; latency/memory targets need a representative model and owner-approved criterion before optimization.

**Execution classification and PR order:** this documentation branch is `AUTO_WITHIN_SCOPE`. L0 private probes and synthetic tests are `AUTO_WITHIN_SCOPE` once an SDK already available under accepted terms is identified. Changes that replace established ARS2D/GLB behavior require `AUTO_IF_PARITY_PROVEN`. Public format/ABI/capability or production packaging is `PROPOSE_DECISION` through an ADR and license review. Publishing the owner's model or redistributing Core without applicable rights is `STOP_CONFLICTING_ACTION`. Keep L0, L1, L2, L3 and L4 in separate reviewable PRs; every PR names its exact parent SHA, SDK version, accepted feature inventory, test logs and still-open HOLDs. L1/L2 may be combined only when the smallest independently runnable renderer slice demands it and the diff remains reviewable.

**Next actionable decision:** owner reviews whether post-v0.1 optional integration and the applicable SDK/model terms are acceptable.
