# F4 public-input delta and staged isolation contract

The owner selected **arbitrary public-user MOC3 input** during F4 completion on 2026-10-19. This supersedes trusted-local-only as the eventual product target. It does not grant redistribution rights for the private sample or activate an unfinished importer. The implementation must accept hostile input as data and reject unsupported/invalid features; it must not promise that every MOC3 file is renderable or author-equivalent.

| ID | Boundary and frozen acceptance |
| --- | --- |
| F4-P01 | Default-OFF Windows native MOC parser worker, outside the trusted host. Host supplies bounded bytes and actual texture count, not an arbitrary execution command. A successful result is only sandboxed parser preflight, never authorization to parse the same untrusted bytes again in the trusted renderer process. |
| F4-P02 | A new zero-capability AppContainer profile per bounded launch, no network capabilities; explicit inherited stdio handles only; restricted child creation; Windows Job with one active process, 512 MiB process/job memory, two-second CPU and five-second wall limit. Read-only access to a dedicated worker copy only. Create the child suspended, attach the Job, then resume. No fallback to ordinary process execution. Delete the temporary profile after worker termination; prove cleanup. |
| F4-P03 | Probe actual AppContainer identity, deny access to a generated owner-only file outside the worker folder, deny an outside write and deny a real loopback connection to a live test listener. Prove child-process restriction, timeout, memory enforcement, crash containment and bounded output. Probes contain no real user secrets and never reset a GPU. |
| F4-P04 | Worker validates the bounded binary envelope before the evaluator. Malformed/truncated/generated mutations are isolated; authorized private sample can supply a positive local witness. Public corpus coverage is separate from private fixture success. Host parses only fixed status tokens from a capped pipe, never model-controlled diagnostic text. |
| F4-P05 | Whole public importer remains unavailable until manifest/path/PNG/physics admission and persistent evaluator/typed-snapshot transfer are also isolated, broker output is independently validated before host allocation/GPU upload, and replacement/cancellation/CPU-GPU commit negatives pass. Do not route public input into CORE-LIVE or the installed trusted-local consumer. |
| F4-P06 | Qualification still needs coverage-guided native fuzz/sanitizer evidence, declared supported subset, redistributable fixtures, reference fidelity where claimed, SDK ABI/capability/package contract and an explicit release decision. Windows isolation evidence cannot qualify Linux. |

Threat: model bytes may exploit the independent native parser, loop forever, allocate memory, spawn descendants, flood the pipe, or try to read/write host files/network. The host binary, broker implementation, system runtime and selected worker binary are trusted; an attacker already able to alter host code under the same Windows account is outside this model. AppContainer is an OS boundary, not a proof of parser correctness. It retains normal Windows platform access and its own temporary profile; no claim of zero filesystem access is made.

Implementation references: [Microsoft AppContainer isolation](https://learn.microsoft.com/en-us/windows/win32/secauthz/appcontainer-isolation), [launch attributes and profile lifecycle](https://learn.microsoft.com/en-us/windows/win32/secauthz/implementing-an-appcontainer), [CreateAppContainerProfile](https://learn.microsoft.com/en-us/windows/win32/api/userenv/nf-userenv-createappcontainerprofile). The selected policy uses zero capability SIDs, explicit handle inheritance and fail-closed OS setup rather than a CLI permission flag.

Preacceptance oracle refinement: initial probes incorrectly assumed every network block returns WSAEACCES. This machine's nonblocking loopback probe instead observed no completion. Final acceptance distinguishes explicit denial from **no connection observed in a frozen two-second poll window**, with successful host-to-listener controls before/after and no accepted sandbox connection. Success or SO_ERROR=0 completion is a failure. This is a bounded observed loopback result; WFP drop correlation and IPv6/UDP/remote-egress qualification remain HOLD. Earlier failed diagnostic packets are retained. [Microsoft documents AppContainer packet drops](https://techcommunity.microsoft.com/blog/coreinfrastructureandsecurityblog/diagnosing-network-isolation-issues/2511562); a timeout by itself is not attributed to policy enforcement.

Worker bootstrap uses a pipe-only Windows subsystem and static CRT in the tested build. No LowBoxConsoleEnabled registry setting is changed. Stderr goes to an inherited NUL handle, independently of the 64-byte stdout protocol limit: parser diagnostics are neither returned to the host nor stored without a bound. A stdout-flood probe still must terminate the Job. Per-worker ACLs replace inheritance with owner/SYSTEM access and AppContainer read/execute only.

CPU guard refinement: the first busy-loop trial exposed that Windows checks the configured Job CPU limit periodically; it did not satisfy the frozen upper-bound witness. The trusted launcher now additionally samples process user CPU every 10 ms and terminates the Job at two seconds, retaining the original Job limit and five-second wall limit. The probe keeps its original 1.9-3.0 CPU-second acceptance window. [Microsoft's documented periodic enforcement](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_limit_information) is not an excuse to widen the measured security limit.

The child receives a sorted minimal Unicode environment containing Windows/System32 paths and the platform LOCALAPPDATA path required by CreateProcess to locate the AppContainer profile. Other application variables and credentials are excluded. A generated host environment sentinel must be absent inside the actual AppContainer. Omitting LOCALAPPDATA failed closed with Win32 ERROR_ENVVAR_NOT_FOUND; the fix adds that one platform location rather than restoring the host environment. The launcher itself is trusted and handles no model parsing. Per-worker read/execute ACLs do not claim to eliminate the platform's normal AppContainer-readable system resources.
