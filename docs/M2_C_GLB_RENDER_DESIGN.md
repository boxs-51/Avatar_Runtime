# M2-C private GLB 3D rendering design — 2026-10-17

**State:** implementation design candidate, not a G04 verdict or public capability. **Stack parent:** draft M2-B PR #32 at `6e3e013c8211a7a2c20ea3520ca2a5be599f79fb`; M2-A PR #31 and M1-D PR #30 are still unmerged. This document defines the next source increments only. D06 post-loss lifetime and D08 actual device loss/recovery retain `HOLD_CARRY_TO_M2`.

The goal is to read a C2-validated embedded `glb-gltf2` from `ValidatedCpuModel::glb()`, render a default-pose skinned and morphed mesh into a host-owned offscreen target, and compare actual pixels and depth on WARP and a named GPU. G04 requires mesh, skin, morph, camera, offscreen readback and resource-boundary evidence. Animation playback, VRM, public `ars_runtime_render`, model activation and mode switching remain outside this increment. The public G00 technical-method, G01 and G02 gates remain HOLD independently of a green M2-C test.

The projection accepts only a published, validated immutable model. It rejects missing 3D representation, `vrm1`, required unsupported extensions, non-triangle primitives, extra joint sets and material features outside the implemented render profile before any D3D resource allocation. Malformed GLB remains the C2 parser's `ARS_E_BAD_ASSET` responsibility; a structurally valid but unrenderable feature returns `ARS_E_UNSUPPORTED`. Checked budget failures return `ARS_E_OUT_OF_BUDGET`. The previous scene and target remain unchanged on all preflight failures.

## Proposed private render contract

1. **Scene and pose.** Use the declared default scene; when absent, require an explicit, range-checked scene index from the caller. Traverse reachable roots once in deterministic declaration order. Local transform is the node matrix or `T * R * S` in glTF column-vector convention; world transform is `parent_world * local`. Reject nonfinite derived values and unsafe float conversion. Begin with default node transforms and node weights overriding mesh weights; a private test pose may supply bounded joint transforms and morph weights. It does not start GLB animation clips. Unreachable nodes cannot produce draws.
2. **Morph before skin.** For each primitive, compute `p_morph = p_base + sum(weight[t] * delta_position[t])` and analogous available normal/tangent deltas, then renormalize direction vectors. For a skinned mesh, use joints in `skin.joints` order, with the inverse-bind matrix at the matching slot or identity if absent. Transform positions by the four weighted joint matrices; use direction-appropriate normal transforms and renormalize. For an unskinned mesh, apply the mesh node world transform. A dedicated fixture must distinguish morph-then-skin from skin-then-morph and catch a transposed matrix or wrong joint index. The glTF 2.0 source of truth is the [Khronos specification](https://github.com/KhronosGroup/glTF/blob/main/specification/2.0/Specification.adoc).
3. **Camera and depth.** glTF coordinates are right-handed, +Y up; camera looks along local −Z. An explicitly selected validated glTF perspective/orthographic camera or a validated host-provided private camera is required. No arbitrary auto-camera based on mesh bounds. A missing perspective `zfar` uses an infinite-far projection; missing aspect uses target width/height. Convert to D3D clip depth `[0,1]` without changing source handedness. Allocate a private same-size depth texture, clear depth to 1, depth-test opaque/masked triangles, and restore the host DSV/state. Resize creates new target/depth resources and a new viewport; it never rewrites GLB coordinates.
4. **Material profile.** Before claiming G04, support default/base color factor, embedded PNG `baseColorTexture`, metallic/roughness factors and texture, and `OPAQUE`, `MASK`, `BLEND` alpha modes. Project referenced texture/sampler fields into owned records and implement their declared wrap/filter behavior. For the private deterministic image method, use one fixed directional key light plus fixed ambient and a defined metallic-roughness BRDF; no implicit animation, environment map, shadows or custom shader. Normal, occlusion, emissive or extension material features that the renderer has not implemented are `UNSUPPORTED` at preflight, even if C2 accepted their structure. Opaque/masked draws use depth; blend draws are sorted back-to-front with stable node/primitive index ties. Every supported combination needs a fixture, including transparent overlap and cutoff boundary.
5. **Color and composition.** Decode glTF base-color texture sRGB to linear for lighting; metallic/roughness channels stay linear, according to [Khronos glTF 2.0](https://github.com/KhronosGroup/glTF/blob/main/specification/2.0/Specification.adoc). Clamp/tone-map the deterministic linear result, encode for the existing `R8G8B8A8_UNORM` offscreen target, then premultiply by alpha **in target numeric space** before the same `ONE / INV_SRC_ALPHA` blend used by M2-B. This explicitly matches the current private 2D byte-space target contract; it is a compatibility choice to test, not a general linear-light compositing claim. Any later HDR/sRGB-target change requires new golden pixels and an ADR review before G03/G04/G05 promotion.
6. **GPU and lifetime.** Dry-run checked byte arithmetic and all feature/camera/material selection before GPU allocation. Proposed ceiling: `min(host-provided limit, 256 MiB)` for owned GPU buffers/textures, plus `64 MiB` transient CPU pose/deformation scratch; the host-owned color target is excluded, the private depth target is included. C2's 2-million-vertex, 256-joint aggregate, 64-morph-per-primitive and 128-MiB decoded-pixel limits remain upstream ceilings, not guaranteed renderability. Return `OUT_OF_BUDGET` without changing the old scene/target when the M2-C limit is exceeded. On R, create the full new resource bundle before target mutation, retain bundle and CPU snapshot through `QueryRetirement`, and release only after exact completion or a proved lost-device host teardown barrier. A normal render on a physical GPU does not prove D06/D08.

The test oracle must inspect numeric readback pixels and depth, not just `HRESULT`, CI green or a screenshot. Include a deliberately wrong skin/morph-order negative control and an over-budget/unsupported-resource negative control. A test that falls back from hardware to WARP must say so and cannot count as physical evidence.

## Gate and device-loss boundary

G04 can be reconsidered only after C0–C2 pass together on an exact integrated source and the host can submit the committed 3D pose/camera to the offscreen pass; a private source slice by itself is **partial**. G03 remains tied to 2D host integration, and G05 requires both renderers plus the 100-switch and OOM rollback transaction. G00 technical-method, G01 and G02 are separately held and cannot be inferred from M2-C CI.

Safe WARP fault injection may exercise `DXGI_ERROR_DEVICE_REMOVED/RESET` control flow, quarantine, pin retention, rejection of old resources, teardown acknowledgement and replacement-device logic without inducing TDR. It cannot make `ID3D11Device::GetDeviceRemovedReason()` report an actual driver reset or prove post-loss live-object cleanup. Keep D06/D08 `HOLD_CARRY_TO_M2` until a disposable reset-capable Windows GPU runner and an integrated host teardown barrier exist. Do not run `dxcap -forcetdr` on the shared workstation; [Microsoft's device-loss guidance](https://learn.microsoft.com/en-us/windows/uwp/gaming/handling-device-lost-scenarios) describes it as a forced GPU timeout/reset.
