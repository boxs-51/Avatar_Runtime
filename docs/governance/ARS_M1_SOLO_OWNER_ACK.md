The one Human Repository Owner (boxs-51) alone can accept reserved risk, amend governance and public ABI/security boundaries, authorize protected setting changes, production activation and **each exact PR merge**. A GPT Developer, Auditor, two threads, role labels or use of the same GitHub token do not create multiple independently verified actors.

## Direct YES / REVISE / HOLD

A clearly scoped directive in the owner's active ChatGPT conversation or a verified, genuine owner GitHub comment may determine an exact decision without simulated bilateral signatures. Developer records issue, source/path manifest, PR, base/head exact SHA, stage, risks and exclusions, timestamp, origin, and explicit granted operation. When a GPT posts a chat instruction into GitHub through the connected account, label **owner instruction relayed by GPT**; a relayed comment is not independent cryptographic owner signoff. Silence, a generic “go ahead”, design-freeze consent or neighboring PR's YES does not confer another permission.

## Authority tiers and hard stop

- **T0 routine:** investigation, technical design, scoped documentation, tests, CI, safe remediation within an existing authorized pathset. No implicit main merge or protected configuration edit.
- **T1 significant:** shared path custody, material schema/API/ABI changes, cross-component architecture/stack parent changes; obtain explicit exact-scope approval before performing material changes.
- **T2 critical:** authentication/security boundary, destructive operations, native sandbox, privacy/retention, production activation, policy exception/adoption, GitHub protected configuration, **EXPLICIT_MERGE_ACK** for **every PR**. T2 never comes from a design-only YES.

The strictest applicable tier wins; changed risk/path/HEAD/parent requires a new owner decision. Human instructions cannot waive GitHub platform rules, proven P0/P1 defects or required source and CI evidence. Existing accepted ARS-SOLO-OWNER-001 exception only covers a transparent lack of independent actor for a specific process, not the quality or results of tests.
