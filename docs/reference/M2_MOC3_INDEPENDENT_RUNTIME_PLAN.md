# Optional MOC3 support without the official Live2D SDK — plan (2026-10-18)

**Status:** proposed implementation contract; `HOLD_DYNAMIC_LIVE2D`. **Stack parent:** `m2/live2d-l0-preflight` (draft PR #47). The owner has deferred use of the official Live2D SDK. This document supersedes the SDK-dependent implementation path in `M2_LIVE2D_DYNAMIC_ADAPTER_PLAN.md`; its local sample inventory, privacy restriction, renderer/lifecycle requirements and unresolved gates remain valid. It does not change the v0.1 non-goal for proprietary Live2D integration or promote G00–G05, D06 or D08.

## Decision and evidence

The [official model3 specification](https://github.com/Live2D/CubismSpecs/blob/master/FileFormats/model3.json.md) describes the manifest and its file references, not the drawable geometry and deformation hidden in `.moc3`. Our existing preflight checks a MOC3 magic/header and PNG headers only; it has not validated or evaluated the MOC3. A portrait-to-ARS2D conversion is a useful static fallback, not dynamic model support.

| Option | Evidence and fit | Decision for the first slice |
| --- | --- | --- |
| [Purism Core](https://github.com/SakuraMotion/PurismCore), independent C99 MOC3 evaluator | Its [API](https://github.com/SakuraMotion/PurismCore/blob/master/docs/API.md) exposes MOC validation, parameters, update and drawables. Upstream labels the source MIT and publishes a [1.1.0 release](https://github.com/SakuraMotion/PurismCore/releases), but sample compatibility, renderer fidelity and security are unverified here. Its [compatibility guide](https://github.com/SakuraMotion/PurismCore/blob/master/docs/COMPAT.md) warns that the v5 ABI omits newer offscreen/blend data. | **Preferred proof-of-compatibility candidate**, pinned to a reviewed commit/tag, built from source for the local Windows toolchain. Use its v6 API only after checking the model's required features. Do not ship a binary or claim license clearance from this table. |
| [Mocari](https://github.com/Eatgrapes/Mocari), independent Rust runtime | Its [crate API](https://docs.rs/mocari/latest/mocari/) exposes model loading, parameter updates and generated meshes, but upstream calls the project experimental. A Rust helper/FFI bridge adds a second toolchain and ownership boundary. | Reserve as an independent cross-check or fallback if it passes the same private sample and feature gates. No assumption of full fidelity. |
| Own MOC3 parser/evaluator | A converter still needs correct binary parsing, deformers, parameters, drawables and newer feature semantics. Manifest JSON plus atlases cannot reconstruct these. | Defer until a bounded incompatibility in both candidates is demonstrated and the required format subset is documented. |
| Offline static/sampled-pose converter | Can emit a portrait or finite pose set into existing assets, but cannot represent arbitrary parameter motion, physics and masks without a new format. | Keep as an explicitly limited preview; it cannot close `HOLD_DYNAMIC_LIVE2D`. |

The proposed system boundary is **local MOC3 evaluator → owned, backend-neutral per-frame drawable snapshot → host-owned D3D11 offscreen renderer**. A converter may serialize the same snapshot for inspection, but the production dynamic path must evaluate each frame. Do not stretch ARS2D v0.1's single-portrait/128 MiB parser contract to accommodate this model.

## Constraints

- No official Live2D SDK headers, binaries, Framework or SDK-dependent converter in this track. `ARS_ENABLE_CUBISM` currently checks `ARS_CUBISM_SDK_ROOT` and fails closed; a later implementation PR must replace this with an explicitly named independent-backend flag and remove the SDK requirement. Default stays OFF. Until a real adapter exists, ON must still fail clearly.
- The owner's `ulvm2_0002` model and all derived images, frames and archives stay local and gitignored. The owner permits use but forbids publishing it in the public repository. Public evidence contains only sanitized counts, hashes, versions and verdicts. A library's MIT label does not grant rights to the model or settle all distribution questions; record dependency notices and review applicable model/runtime terms before packaging.
- The local sample has a 2,727,808-byte MOC3 and five 4096×4096 atlases: 335,544,320 decoded RGBA bytes (320 MiB). Its `model3.json` references Physics and DisplayInfo but no expressions or motions; 35 expression sidecars are unreferenced. Private texture accounting and host residency must be designed separately from ARS v0.1's 128 MiB pixel ceiling. No silent global-limit increase.
- MOC3 and sidecar inputs cross a parser trust boundary. The first spike accepts only an explicitly chosen local asset under a contained root. Public arbitrary-file import is out of scope until parser hardening, limits, fuzz/negative tests and process-isolation decision are reviewed. Upstream security claims are useful leads, not proof for this product.

## Reviewable slices and acceptance gates

| Slice | Implementation | Evidence required before advancing | HOLD on failure |
| --- | --- | --- | --- |
| I0 — independent evaluator spike | Pin source/tag and checksum; inspect license/dependencies and build on the actual Windows compiler without official SDK files. Make a **private**, bounded probe that validates the sample, records MOC version and parameter/part/drawable/texture/mask/blend/offscreen counts, and runs default plus two changed parameter poses. Capture geometry/opacity/order hashes only; never export sample bytes. | Reproducible toolchain and exact source revision; nonzero expected drawable inventory; two changed poses produce changed drawables; invalid magic, truncation, unsupported version and oversized input fail cleanly. Cross-check at least one inventory/pose with Mocari if it can parse the sample. If not, record the exact mismatch. | `HOLD_MOC3_EVALUATOR`, `HOLD_PARSER_TRUST` |
| I1 — bounded model and snapshot contract | Define ownership of aligned MOC/model buffers, update thread and immutable snapshot. Snapshot contains stable drawable identity, vertices/indices/UV, atlas index, render order, opacity, multiply/screen colors, blend, clipping/inverted-mask membership and offscreen groups **when present**. Reject unsupported required features before committing a snapshot. Apply separate MOC, drawable/vertex, atlas decoded/resident and per-frame allocation ceilings. | Validated local inventory, deterministic repeated-pose hashes, parameter min/default/max and repeat behavior, typed unsupported/OOM errors, no mutation of prior scene on failed admission. Physics and expression handling remain separately tracked until exercised. | `HOLD_UNSUPPORTED_SAMPLE_FEATURE`, `HOLD_TEXTURE_BUDGET` |
| I2 — D3D11 renderer and host custody | Render observed snapshot features to the existing host-owned offscreen target; manage same-device/generation resources, state save/restore, query retirement and resize/close. No portrait substitution may count as a dynamic result. | Three parameter poses have numeric WARP pixel readbacks (alpha edges, ordered overlap, masks, blend and atlas selection) against an independently rendered reference; fix color-space/UV conventions and tolerances **before** judging results. Repeat on a named GPU where available. Wrong thread/device, stale target, resize, OOM and failed draw leave the host state and previous scene intact. | `HOLD_RENDER_FIDELITY`, existing physical GPU/device-loss HOLDs |
| I3 — optional behaviors and release decision | Add physics and only those expression/motion resources explicitly selected and linked by a later manifest decision. Run sustained updates and teardown. Write an ADR for the private/optional feature, dependency packaging, license and public-input trust model. | Physics on/off changes measured pose when expected; expressions are linked deliberately rather than discovered from stray files; repeated load/update/resize/close and device-generation changes retain no leaked resources. Independent review and public-safe evidence packet. | `HOLD_DYNAMIC_LIVE2D` until all accepted behaviors pass; public activation separately gated |

I0 should be a small tool/probe PR; I1 a snapshot-contract PR; I2 a renderer PR; I3 a behavior/ADR PR. Each PR names its parent SHA, dependency revision, local-only evidence, negative cases and remaining HOLDs. A successful compile, MOC parse, CI run or stack merge alone closes none of the pixel, physical device-loss or release gates. D06/D08 physical-loss tests remain HOLD without a resettable GPU runner.

**Fallback rule:** if Purism Core fails the sample or requires unsupported features, test Mocari against exactly the same inventory and pose contract. If neither passes, preserve the static preview and publish a narrow incompatibility report; do not invent a lossless MOC3-to-ARS2D conversion. Resume an own-parser proposal only with a bounded format subset, independent oracle and parser security budget.

**Immediate next implementation:** I0 only. The result decides whether the independent runtime path is viable; no SDK acquisition is needed. Until that evidence exists, dynamic MOC3 support remains `HOLD_DYNAMIC_LIVE2D`.
